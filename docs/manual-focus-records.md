# 手动专注记录

入口：编辑待办 → 添加专注记录（默认绑定该待办）；也可从统计 → 查看专注记录 → 手动添加记录进入。

日期和开始时间默认取打开弹窗时的本地时间，草稿在页面重建后保留。输入专注分钟数，或选择 25/30/45/60/90/120 分钟，自动计算只读结束时间。编辑记录也使用开始时间和时长。时长必须为正整数，结束必须在当天 24:00 前；日期不能晚于今天。统计入口保存后显示记录所在日期，待办入口保存后返回原编辑弹窗。任务可改选，备注可选。

待办入口将已保存任务的 id 作为 defaultTaskId 传入共用 ManualRecordDialog；保存时把用户最终选择的 taskId 经 TodoViewModel 传给同一个 FocusRepository.saveManual，不创建额外的数据表。

## 数据及统计

- 沿用 focus_sessions 表，新增 source（TIMER / MANUAL）及可空 note。数据库 6→7 迁移将旧记录默认标为 TIMER。
- 手动记录使用 FINISHED 状态、正向计时类型、零计划时间；有效时长等于起止时间差，分心为零，不增加“完成番茄”数量。
- 原有日、周、月、小时分布、热力图和历史查询均直接读取同一记录，Room Flow 在增删改后通知统计刷新。
- 任务关联存入 taskId，标题保留快照；新增 taskFocusSeconds 查询接口同时汇总 TIMER 和 MANUAL。当前项目尚无独立的任务时长统计页面，本次没有新增该页面。
- 计时器的 latest / observeLatest 仅读取 TIMER，避免补录遮住活动计时或干扰休息轮转、后台分心结算。
- 手动更新和删除 SQL 限定 source = MANUAL 且 status = FINISHED，拒绝通过补录功能修改正常计时记录。
- 本次不做重叠时间去重，统计仍按每条记录累加；不支持跨天补录。

## 验证

ManualRecordTest 覆盖两小时计算、非法输入、数据库迁移、日/周/月及每日热力图汇总、任务汇总更新、编辑移动日期、删除，以及补录期间活动计时和分心结算。
FoundationTest 覆盖历史入口、实时预览、重建恢复、保存、编辑和删除确认。

验证结果：assembleDebug、lintDebug 和 connectedDebugAndroidTest 通过，API 36 模拟器共 47 项测试，零失败。

时长输入与待办入口优化后：47 项回归测试通过；新增待办入口专项测试单独运行通过，验证当前时间默认值、默认任务绑定、120 分钟自动得到 16:00、草稿重建及任务累计 7200 秒。
