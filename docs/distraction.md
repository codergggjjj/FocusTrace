# 前后台分心检测阶段

## 规则与计时口径

遵循设计书第 16–21、24、53–54 节。Application 注册 ProcessLifecycleOwner，Observer 仅转发进程事件，不依赖某个 Activity。普通模式默认 3 秒，严格 0 秒、宽松 10 秒，可自定义 0–86400 秒。

只在 FOCUSING 状态记录离开。暂停、休息、空闲、已结束时忽略；锁屏导致进程进入后台也视为离开。阈值取离开时的配置，后续修改不会改变这一次事件的判断。

设计书的有效专注时间和分心时间分开计算：达到阈值时扣除整段离开时间；未达到阈值时补回这段时间。后台期间暂存有效进度，返回后判定，因此番茄钟不会仅因长时间离开而完成。正向计时采用同一规则。

阈值比较以毫秒进行。沿用设计表的 durationSeconds 和 distractionSeconds 整秒字段，每个事件向下取整；严格模式的短暂离开可能显示 0 秒，但仍计为一次。总秒数等于各条事件秒数之和。内部有效专注保留毫秒精度。

## 持久化与恢复

Room 升为版本 3，在会话中新增离开的墙上时间、单调时间、开机编号和阈值快照。1→2→3 非破坏性迁移保留已有任务及记录。

返回处理在一个 Room 事务中插入事件、更新次数与总秒数、清除待处理离开状态并调整计时锚点。重复回调不会重复插入，写入失败会整体回滚。应用级有序队列保留回调发生时的时间，避免把数据库排队延迟算成后台时间；失败时显示提示并重试，界面操作等待已经排队的生命周期事件完成。

同次开机用单调时间计算时长；重启设备后回落墙上时间。已落库的离开状态可在进程重新创建后结算。设备重启且系统时钟改变时无法精确还原，负差值按零处理；墙上时间仍如实保存，修改系统时间可能使明细中的返回时间早于离开时间。

ProcessLifecycleOwner 自身对后台事件有延迟，用于避免配置变化误触发。本应用按收到的进程回调计时，不能保证捕捉没有产生进程后台事件的极短切换。若系统在后台回调或数据库提交之前立即杀死进程，该次离开可能无法恢复；本阶段不增加前台服务或高频写盘。

休息在后台结束且启用了自动下一轮时，等待回到前台再开始新一轮，避免后台自动启动的专注没有对应离开事件。

## 界面与验证

专注页提供判定阈值设置，本轮显示分心次数、总时间和明细弹窗。完整报告及统计仍留到下一阶段。

验证涵盖 0/3/10/自定义阈值边界、重复回调、暂停/休息/空闲排除、超出番茄截止时间的离开、单调时间及队列延迟、重开数据库和模拟设备重启恢复、事务回滚重试、1→3 迁移，以及模拟器实际回桌面和返回应用。Activity 重建不应新增分心事件。

最终验证：assembleDebug、lintDebug、connectedDebugAndroidTest 全部成功；API 36 模拟器 20 项测试通过，0 失败；Lint 0 错误、2 项既有版本提示。最终 APK 安装和冷启动成功，判定阈值弹窗视觉检查通过。
