# 待办排序

在“待完成”筛选旁点击排序图标，打开“调整待办顺序”。每条任务提供上移、下移和置顶按钮，点击后自动保存，完成按钮返回任务列表。首项上移/置顶、末项下移自动禁用。至少两项待完成任务时显示入口；已完成筛选不显示。

顺序持久化到 Room 的 `TaskEntity.sortOrder`。新建任务和自动生成的重复待办放在最上面；编辑标题、计时模式、重复规则不会覆盖顺序，完成后恢复任务时保留其排序值。已完成列表保持创建时间倒序。

数据库升级为版本 9，8→9 迁移仅增加默认值为 0 的排序列，保留任务、专注及分心记录。旧任务默认维持原有创建时间倒序，首次需要时规范化排序值。备份增加可选 `sortOrder` 字段，格式版本仍为 1；旧备份缺失字段时使用 0，按原排序展示。

DAO 在事务中读取当前待完成列表并调整位置，避免把 UI 旧快照覆盖回数据库。普通相邻移动只更新两行；置顶或处理旧数据的相同排序值时更新必要的排序行。处理在数据库协程中执行，不在 UI 排序。弹窗使用带稳定任务 ID 的 LazyColumn 和 Material 3 按钮，保存期间禁用重复操作。

## 修改范围

- TaskEntity、TaskDao、TaskRepository：排序值、查询、新任务置顶、事务移动及编辑时保留排序。
- FocusTraceDatabase、AppContainer、schema 9：显式迁移与注册、Room 自动导出的 schema。
- TodoScreen、TodoViewModel、TaskOrderDialog：排序入口、操作状态及轻量列表弹窗。
- BackupFormat：保存顺序并兼容旧备份。
- TaskOrderTest、TaskOrderUiTest、BackupRepositoryTest：迁移数据保留、排序持久化/旧编辑、页面重建与备份恢复检查。
- app/build.gradle.kts：测试资源打包等待 Room schema 导出，避免首次迁移测试缺少新 schema。
